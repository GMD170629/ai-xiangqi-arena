# 斗兽棋 · Presentation 规范

## 目标

首版视觉上要让斗兽棋成为一个有辨识度、节奏轻快的“AI 动物竞技场”，但所有视觉实现都必须留在斗兽棋模块内部，不能污染平台 Core。

## 视觉重点

### 棋子

每种动物要有清晰轮廓和等级信息，优先保证缩小后仍可辨认。

建议同时支持：
- 动物插画/图标
- 中文名称
- 1-8 等级
- 蓝/红阵营区分

### 地形

棋盘必须清晰展示：
- 普通陆地
- 河流
- 陷阱
- 兽穴

河流、陷阱、兽穴可以承担大部分趣味动效，而不是给整个客户端堆叠夸张特效。

## 首版动效

- 普通移动：短促平滑位移。
- 捕获：攻击方略微前冲，被捕获方快速缩小/淡出。
- 鼠入水：轻量水波。
- 狮虎跳河：明显但快速的跨越弧线/拉伸效果。
- 进入敌方陷阱：短暂“陷落”反馈并显示弱化状态。
- 冲入兽穴：局部聚焦 + 胜利反馈。
- AI 思考：属于平台通用 UI，不写进棋盘状态机。

## 趣味提示

趣味提示由“游戏事件 + AI 人格”共同触发，但文案不得影响规则。

例：

- 鼠吃象：`小的未必怕大的。`
- 狮虎被河中鼠挡住：`一只鼠，堵住了整条跳河路线。`
- 进入陷阱：`糟糕，它踩进去了。`
- AI 连续两次非法动作：`它好像还没完全适应这片丛林。`

这些文本应通过事件 key 映射和本地化系统管理，禁止散落硬编码。

## UI 交互边界

棋盘上的棋子可以：
- Hover / Focus 查看动物信息。
- 展示上一步移动。
- 展示 AI 正在考虑的公开状态（如果产品决定展示）。

棋盘上的棋子不可以：
- 被人类拖动。
- 点击后出现“可走位置”供人类选择。
- 通过任何直接操作形成 Action。

人类对棋局的唯一影响渠道仍然是 Commander 与 AI 的自然语言交互。
