# 12 · Platform-first 原则

本项目真正的产品不是某一种棋类，而是：

> **AI 对弈 + 人类通过语言影响己方 AI。**

具体棋类只是承载这个关系的竞技场。

## 三层产品结构

### 1. Platform Core

跨所有游戏共享：
- Match 生命周期
- AI Player
- Commander
- AI Personality
- AI Provider
- Prompt/Protocol
- 对局记录
- 通用聊天与状态 UI

### 2. Game Module

每个棋类独立拥有：
- 规则
- 状态
- 动作
- AI 状态序列化
- 专属棋盘/场景 UI
- 棋子/单位资源
- 专属动画与音效
- 规则版本

### 3. Presentation Shell

负责把当前 Game Module、双方 AI、Commander 面板和对局信息组合为完整游戏页面。

## 首版为什么选择斗兽棋

首版由象棋切换为斗兽棋，原因不是产品从“象棋”变成了“斗兽棋”，而是斗兽棋更适合快速验证核心玩法：

- 规则更短，更容易让不同规模模型理解。
- 单局通常更紧凑，更适合快速重复测试。
- 动物等级、鼠吃象、河流、陷阱、兽穴天然具有趣味反馈。
- AI 做出“聪明/离谱”的决定时更容易被普通玩家理解。
- 视觉表达空间更大，适合作为首个 Game Module 验证 Presentation 抽象。

## 判断功能是否属于 Core

新增功能前问：

> 如果把斗兽棋换成五子棋，这个能力还成立吗？

如果成立，优先放 Core。

如果涉及动物、棋盘坐标、河流、落子棋子等具体规则或表现，则属于对应 Game Module。

## 长期目标

未来可以逐步增加：
- 五子棋
- 中国象棋
- 国际象棋
- 黑白棋
- 其他回合制、状态明确、动作可结构化描述的棋盘游戏

新增游戏不应改变产品的核心身份：**AI 是棋手，人类是影响 AI 的 Commander。**
